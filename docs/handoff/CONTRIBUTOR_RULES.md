# Contributor Rules

Mandatory rules for developers, coding assistants, contributors, and future maintainers working on this project.

* Before making changes, read every file in docs/handoff/.
* Before making changes, inspect the current project structure.
* Do not assume the previous coding assistant or developer completed something unless the code proves it.
* Do not add backend unless the task clearly asks for it.
* Do not add real encryption unless the task clearly asks for it.
* Do not add AI systems until the AMI project is reviewed.
* Do not use the word server in the user-facing UI.
* Do not make the app tactical-first.
* Keep AegisNet civilian-first and family-friendly by default.
* Keep advanced Mission Mode features optional.
* Update docs/handoff/UPDATE_LOG.md after every build.
* Update docs/handoff/CURRENT_STATE.md when the project state changes.
* Update docs/handoff/NEXT_STEPS.md when tasks are completed or new tasks are discovered.
* Update docs/handoff/LESSONS_LEARNED_FROM_AMI.md if an AMI lesson affects future work.
* If something is broken, document it clearly.
* If something is mock-only, document it clearly.
* If a decision is made, add it to DECISIONS.md.
* If a feature is copied or adapted from AMI later, document what was copied, what was rewritten, and why.
